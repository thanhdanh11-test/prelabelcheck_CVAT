# Contracts
CvatCacheVault.create({storage,crypto,locks,origin}) -> unlock(password), lock(), seal(name,bytes), open(name,envelope), readOrigins(key), writeOrigins(key,value), migrateOrigins(), reset(), wrapStore(store); unlocked/exists getters.
Header key cvat-cache-vault:v1; version1, salt16 bytes, PBKDF2 SHA-256 600000 iterations, random vault ID, encrypted fixed verifier. AES-GCM IV12 random bytes/tag128; AAD includes origin/vault ID/record name. Header validation fixed parameters, no attacker-controlled iteration count. Password minimum12 chars, maximum1024. Tab keys non-extractable; popup derives a transient extractable key solely for private runtime handoff, then fills transferable byte arrays with zero (not guaranteed memory erasure). Envelope version1 iv byte array/data base64 string. Cloud adapter stores serialized encrypted envelope as Uint8Array; origin JSON encrypted in localStorage under separate namespace. Metadata frame/job IDs, size/timing remain visible.
MUST reject wrong password, corruption, changed header and operations invalidated by lock. Serialize initialization with Web Locks across tabs; compare header before writes. MUST NOT silently reset vault. Encryption before IDB transaction; no awaiting crypto inside IDB transaction. Tests must cover wrong context and mutated ciphertext, not just roundtrip.

Hardening contract (2026-10-23): prepareUnlock(password,header,origin) -> {header,rawKey:number[32]}; acceptUnlock(proof,expectedHeader,expectedLock) -> Promise<void>; describe() -> {header,lockToken}; lockAll() -> void. Shared key cvat-cache-lock:v1 is a public random revocation token. reset() MUST rotate it before awaiting the HEADER Web Lock, including an empty vault. All key operations MUST compare token/header/generation.
Private channel: chrome.runtime.onMessage, channel cvat-cache-private-v1; types status/unlock/lock-all. MUST require same extension ID, exact cache-popup.html sender URL, no sender.tab. status returns a one-use nonce bound to origin/job/header/token, expires in 120000ms; unlock consumes it even on failure. Page postMessage and DOM password controls are FORBIDDEN. Popup resources MUST NOT be web-accessible.
Errors: invalid sender -> ignore; stale/consumed/expired nonce or state -> reject and ask reopen popup; derivation/import/verifier error -> remain locked; storage token write failure -> report failure, do not claim global lock. Local regression: 147/147 tests; deliberately reverting reset revocation produces exit1. Actual installed Chrome messaging gate remains open.
