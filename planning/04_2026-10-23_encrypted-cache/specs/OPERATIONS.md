# Operations
Reload all tool tabs on upgrade. Default locked and no plaintext cloud reads/writes. Unlock/create with separate password and confirmation for creation. Migrate all old origin keys: encrypt, write, decrypt-verify, remove unchanged plaintext only after success; retry idempotently. Then clear old cloud database and upgrade it to version2 (old version1 readers/writers fail closed). Blocked upgrade -> show close-other-tabs error, never claim clean. Old cloud is disposable, sources preserved in encrypted vault. Until unlock, old plaintext may remain; UI must disclose.
Lock drops key, cancels cloud requests and clears cloud buffers; preserve annotation drafts, close preview with RAM draft retained. Resume allows online RAM use. No promise of secure memory erasure. Clear cloud preserves origin vault. Explicit reset confirmation deletes encrypted origin links/header and cloud; forgotten password cannot recover origin history, server annotations unaffected. Legacy plaintext origin cleanup requires migration or explicit reset. Never touch unrelated site storage.
Rollback code can ignore encrypted namespace; do not restore plaintext writes. Reinstalling old extension cannot decrypt vault and old cloud DB version1 cannot reopen upgraded DB. Existing localStorage writers in old tabs require user close/reload; not centrally enforceable.
Failure table: wrong password -> stay locked; quota/corrupt origins -> preserve old record and warn; failed migration -> retry after remediation; lock/reset races -> discard late results. Real browser IDB evidence required locally; company deployment pending.


Hardening: reload extension and every old CVAT tab; enter password only via Chrome extension icon. Lock all same-origin tabs with the explicit button. Closing a tab locks locally. Reset revokes pending unlocks across tabs before deletion. Rollback to the old in-page password UI is not an approved security rollback.
